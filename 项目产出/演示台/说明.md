# 演示台

> 一个页面，把「看的东西」和「能证明的东西」放在一起。
> **双击 `启动.bat`** 即可，无需装任何依赖（Python 3 标准库 + 本机 ssh）。

---

## 为什么需要它

面试时演示一个数仓项目，最尴尬的两种做法：

| 做法 | 问题 |
|---|---|
| 现场敲命令 | 慢、杂、一次输错就中断讲解节奏 |
| 放 PPT / 截图 | 无法回应「能看看吗」——面试官默认截图可以美化 |

所以做成了一个本地页面：**离线页签负责讲清楚，实时页签负责证明是真的**。

---

## 六个页签

| 页签 | 数据来源 | 集群关机能用吗 |
|---|---|---|
| 概览 | `数据/证据.json` | ✅ |
| 链路 | `数据/证据.json` + 真实 DDL | ✅ |
| 证据 | `数据/证据.json` | ✅ |
| 大屏 | `../可视化/dashboard_real.html`（iframe 内嵌） | ✅ |
| 实时 | SSH 现连集群跑查询 | ❌ 需要集群 |
| 问答 | `数据/证据.json` | ✅ |

**四个离线页签是主路径**——线上共享屏幕时，集群往往没开机，或者开机也来不及等 54 分钟。

---

## 界面

- 浅色主题：线上共享屏幕时深色底会被压暗、细线糊掉
- 字号最小 12.5px，正文 15px
- 单页宽 1160px，1280×800 窗口内不出现横向滚动

---

## 设计原则：绝不假装成功

这是整个程序唯一的硬约束。

1. **集群不在线时不返回任何数字。** 实时区显示「未连接 + 具体原因」（SSH 超时 / 密钥拒绝 / HiveServer2 未就绪），不显示上一次的结果冒充本次。
2. **「上次实测耗时」是缓存下来的真实值**，不是估算。第一次跑之前显示「未测过」。
3. **启动进度是轮询出来的真实状态**，不是假动画。
4. **所有数字只有一个来源**：`数据/证据.json`。页面、代码都不重复抄数字——抄两份必然对不上。

## 一键启动三台虚拟机

点「启动集群」会依次调用：

```
vmrun -T ws start "D:\虚拟机\Ubuntu 64-bit.vmx" nogui   # 7168 MB
vmrun -T ws start "D:\虚拟机2\Ubuntu 64-bit.vmx" nogui  # 3392 MB
vmrun -T ws start "D:\虚拟机3\Ubuntu 64-bit.vmx" nogui  # 4096 MB
        ↓
轮询 SSH 直到可用（最多 180 秒）→ 读端口与进程
```

三台合计约 **14.3 GB**。本机可用内存不足时启动会很卡，建议面试前先关掉不用的程序。

> ⚠️ 这段代码只验证过 `vmrun list`（能正确报告 0 台在运行），
> **完整启动流程尚未实测**。第一次用请留出时间，并准备好回 VMware 界面手动点三下的退路。

## 实时查询：为什么耗时差别这么大

| 查询 | 走什么 | 预期 |
|---|---|---|
| ODS 目录与体积 / 分区目录数 | `hdfs dfs` | 秒级 |
| 全月 GMV / 表结构 / 分区清单 | `beeline` 连 HiveServer2 | 10~20 秒 |
| ODS 总行数 | `beeline` 全表 count | 20~60 秒 |

`beeline` 每次都要冷启一个 JVM（约 5 秒）再连 HiveServer2，所以**「秒级」只对 HDFS 命令成立**。
页面上标的是「上次实测」，跑过一次之后就是这台机器上的真实数字。

## 命令行用法

```bash
python serve.py           # 默认 127.0.0.1:8766
python serve.py 9000      # 换端口
python serve.py --open    # 顺便打开浏览器（启动.bat 用的就是这个）
```

只绑 `127.0.0.1`，外部访问不到。
