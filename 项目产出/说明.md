## 📁 子目录

### `数据接入/` —— 真实数据集接入与新链路 ETL（本项目最核心的脚本）

**① ODS 接入（真实数据 → ODS）**

| 文件 | 作用 |
|---|---|
| `check_dataset.py` | 数据集体检：列结构、行数、日期跨度、事件分布、空值率、每日波动。支持 `.csv` / `.csv.gz` / `.zip`（**zip 可直读，不必解压 5GB**） |
| `sample_and_split.py` | 按 `user_id` 哈希采样 + 按天切分。**按用户采样而非按行随机**，避免拆散 session |
| `ods_event_log_ddl.sql` | ODS 建表：`gmall.ods_event_log_di`（9 字段 + dt 分区） |
| `load_ods.sh` | 一键装载：建表 → 31 天分区逐个 `LOAD DATA` → 校验 |
| `profile_ods.sql` | ODS 数据画像（空值率、重复行、取值分布） |

**② DWD / DIM（ODS → 明细层与维度层）**

| 文件 | 作用 |
|---|---|
| `dwd_ddl.sql` | 建 `dwd_event_log_di` / `dwd_purchase_fact_di` / `dim_product` 三张表 |
| `etl_ods_to_dwd.sql` | 清洗 + 去重 + 派生购买事实 + 商品维度（含窗口函数） |
| `dwd_run.sh` | **分步执行器**：把 ETL 切成 5 个可观测步骤，每步写 `dwd_run/status.tsv`；**支持断点续跑** |
| `dwd_progress.sh` | 进度探针：读状态文件 + MR 百分比，供本机看板轮询（**带 run 目录参数**，可复用于 evt_run） |
| `smoke_dwd_1day.sql` | 冒烟验证：只处理 1 天数据，用于快速排除"算子写错"（对比全量 11 个作业 vs 1 天 1 个作业） |

**③ DWS / ADS（明细层 → 汇总层 → 指标层）**

| 文件 | 作用 |
|---|---|
| `evt_ddl.sql` | 建 4 张 DWS + 4 张 ADS 表 |
| `evt_etl.sql` | DWS 四个主题（用户/商品/类目/交易）+ ADS 四个指标 |
| `evt_verify.sql` | 三层校验：分区数 / 交叉对账（GMV 四路收敛）/ 方向性 |
| `evt_run.sh` | **分步执行器（10 步）**：含**启动前自检**（验证 SET 参数真的拼进了分段 SQL）+ 断点续跑 |
| `evt_fix_dws_trade_day.sql` | 一次性修复：重建 `dws_trade_day`（原脚本写错字段名） |

**④ DolphinScheduler 编排（把真实链路接进调度平台）**

> 背景：2026-10-03 审计发现 DS 里**只有旧模拟链路的工作流**，真实数据链路一个节点都没有。
> 这一组脚本就是把新链路建成 16 节点工作流 `gmall_evt_pipeline` 并端到端跑通的产物。
> 详见 `实验分析/实验08_真实链路接入DolphinScheduler.md`。

| 文件 | 作用 |
|---|---|
| `ds_evt_pipeline.py` | 工作流的**建 / 上线 / 下线 / 触发 / 查看**工具。走官方 REST 接口（不手改库，否则 master 内存态看不到）。含 3 个接口坑的绕法：`query-by-name` 不可用要改分页列表、`releaseState` 要枚举名、`timeout` 必须落在 `(0,86400]` |
| `ds_prepare_steps.sh` | 把"一个文件多条 INSERT"的 SQL 切成**每节点一份**。公共 Hive 调优参数从 `dwd_run.sh`/`evt_run.sh` 的 heredoc **抽取**（不重抄），并做启动前自检 |
| `ds_preflight.sh` | 工作流第 1 个节点：服务 / 3 DataNode / 3 NM / **HS2 真可用** / **无残留 beeline** 检查，然后生成分段 SQL |
| `evt_ods_ready.sh` | 工作流第 2 个节点：ODS 就绪 gate。源 CSV 在就重装载；不在就用外部判据核验 31 分区 / 10,630,245 行 |
| `ds_monitor.sh` | 实时进度监视器（部署到集群 `/home/lrh/workspace/`）：每分钟把实例+节点+集群状态写进 `ds_steps/monitor.log`，供本机轮询；实例到终态自动退出 |

### `可视化/` —— ECharts 数据大屏（**两版并存**）

> ⚠️ 同目录下 `dashboard*.html` / `dashboard_data*.js` / `echarts.min.js` **必须始终同目录**（页面用相对路径引用）。

**① 旧版：模拟数据链路（15 张表，2026-08-20~24）**

| 文件 | 作用 |
|---|---|
| `dashboard.html` | 旧版大屏页面（**当前可直接打开**） |
| `dashboard_data.js` | 旧版数据（模拟数据） |

**② 新版：真实数据链路（REES46，1063 万行，2019-10-01~31）**

| 文件 | 作用 |
|---|---|
| `dashboard_real.html` | 新版大屏页面（**双击即开**，需同目录有 `dashboard_data_real.js`） |
| `dashboard_data_real.js` | 新版数据 —— ⏳ **待生成**：集群开机后跑 `bash export_dashboard_real.sh` |
| `export_dashboard_real.sh` | 新版导出脚本（读新链路 6 张表：`ads_active_user_day` / `ads_funnel_day` / `ads_repurchase_day` / `ads_top_product_day` / `dws_trade_day` / `dws_category_event_day`） |
| `csv2json_real.py` | 新版 CSV → JS 转换（列名用新表真实字段名，不再沿用旧表名） |

**为什么两版并存**：新链路与旧链路的**表结构不一样**，有 3 处无法直接对应 ——

| 大屏原本的画法 | 真实数据的情况 | 新版怎么改 |
|---|---|---|
| 漏斗 4 环节（浏览→加购→下单→支付） | 只有 3 环节（view/cart/purchase，**没有订单状态概念**） | 改成 3 环节漏斗 |
| 热销商品显示**商品名** | 没有商品名，只有 product_id / 品牌 / 类目路径 | 用「品牌 · 二级类目」当标签 |
| 订单状态构成（已支付/已取消/已退款） | **完全不存在** | 换成「用户构成（新增/连续活跃/回流）」——旧链路这两项**恒为 0**，真实数据能算出真值 |
| 订单金额（订单总额 vs 支付金额） | 只有成交口径 | 换成「成交金额 + 客单价」双轴 |
| — | ✅ **新链路独有**：类目主题（点分层级路径） | **新增**「一级类目 GMV 构成」 |

### `进度看板/` —— 长任务实时进度条

| 文件 | 作用 |
|---|---|
| `serve.py` | 每 5 秒 SSH 拉一次集群状态 → 算百分比 → 写 `progress.json`，并起本地 HTTP 服务 |
| `index.html` | 进度看板页面，每 3 秒自动刷新，含步骤列表、MR 百分比、ETA |
| `progress.json` | 自动生成，勿手改 |

**用法**：`python serve.py [端口] [dwd_run|evt_run]` → 浏览器开 `http://localhost:8765/`。
配套的集群侧脚本是 `数据接入/dwd_run.sh` / `evt_run.sh`（分步执行并写状态文件）与 `dwd_progress.sh`（探针）。

> ⚠️ **关机前先停本机侧轮询脚本**：RM 停掉后 `mapred job -status` 会挂住不退出，5 秒轮询会堆积僵尸 Java 进程。
