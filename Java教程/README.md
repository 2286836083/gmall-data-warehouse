## 一、为什么这套文档不从 Hello World 讲起

做这套文档前，先对你的材料做了一次扫描：

| 关键词 | 在项目中出现 |
|---|---|
| `JVM` / `堆` / `GC` | **51 / 47 / 23 个文件** |
| `HashMap` / `线程池` | **仅 1 / 1 次** |

这个分布说明一件事：**你不是零基础——JVM 的坑你全踩过，只是不知道那些叫 JVM。**

| 你已经做过的 | 它其实是 |
|---|---|
| `GC overhead limit exceeded` | JVM 的 GC 报警机制 |
| `-Xmx410m` → `-Xmx820m` | JVM 堆上限 |
| 430 万个 `GROUP BY` 组合装不下 | 堆里的哈希表容量 |
| 512 MB 容器没敢设 `-Xmx512m` | 堆外还要留内存 |

所以这套文档的思路是：**从你的故障倒推到原理**，而不是从抽象概念推到例子。
每一份的结尾都有「把你的经历翻译成术语」——那才是面试能用的东西。

## 四、文档里的"可跑验证"都能直接跑

你的本机已确认装有 **JDK 13.0.1（含 javac）**，**不需要额外装环境**。

```bash
java -version     # 确认一下
javac -version
```

每份文档的「可跑验证」小节都给了完整代码和命令，**建议每个都亲手跑一遍**——
亲眼看过一次 GC 空转，和读过一遍描述，是完全不同的两回事。

### ⚠️ 一个会影响实验现象的差异

| 环境 | JDK | 默认 GC |
|---|---|---|
| 你的集群 | **8** | Parallel GC（吞吐量优先） |
| 你的本机 | **13.0.1** | **G1 GC**（低延迟优先） |

**本机做 GC 实验，现象会和集群不一样。** 别把本机的 G1 行为当成集群行为。

## 五、不该现在学的东西

时间有限，这些**明确跳过**：

- Spring / Spring Boot（Web 开发，大数据岗基本不考）
- 设计模式大全
- Java 8 之后的全部新特性（`var`、record、sealed 可以了解，**不要深挖**）
- JDBC / MyBatis
- Java Web、Servlet

大数据岗考的是：**JVM + 并发 + 集合**，不是 CRUD。

## 六、学完之后：接上 P1

```
Java（本目录 01~05）
   ↓
Scala 2.12（Spark 3.5.x 的编译版本，不是 2.13 / 3.x）
   ↓
用 Scala DataFrame API 重写【商品主题那张 DWS】
   ↓
与 Hive SQL 版【行数逐项对账】
   ↓
```

**为什么必须先补 Java 再补 Scala**：
Scala 跑在 JVM 上，内存模型、GC、集合实现全是 JVM 那套。
不懂 JVM 直接写 Scala，就又回到"试出来的"而不是"看出来的"。

## 八、一条贯穿全教程的主线

读完你会发现，"复用 vs 重建"这个模式反复出现：

| 场景 | 复用了什么 | 省掉了什么 |
|---|---|---|
| 线程池 | 线程 | 反复 `new Thread()` 的系统调用 |
| Spark 单会话 | executor + metastore 连接 | 每次约 35 秒启动开销 |
| YARN 容器复用 | 容器 | 反复申请排队 |
| Spark executor | JVM 进程 | 反复启动 JVM |

> **以后遇到任何性能问题，都可以先问一句：
> 「这里有没有什么东西在反复创建又销毁？」**
