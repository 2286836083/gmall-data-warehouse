# 大屏数据导出与切换 · 实操手册

> **这份文档解决什么问题**：大屏是**离线快照**（见 `项目产出/组件详解/06_可视化深潜_从Hive表到一张图.md` 第二章），
> 所以 —— **每次重跑 ETL 之后，大屏的数据就过期了，必须重新导出一次。**
>
> 本文就是"怎么导出、怎么对账、怎么回滚、集群没开时怎么验证"的操作手册。全部命令都是实测过的。
>
> 配套原理篇：`项目产出/组件详解/06_可视化深潜_从Hive表到一张图.md`

## 〇、先记住这一条：大屏数据会过期

| 你做了什么 | 大屏会怎样 |
|---|---|
| 重跑了 DWD / DWS / ADS 的 ETL | ⚠️ **数据已过期**：图还是上一次导出时的数（虽然页面照常打开） |
| 新装了数据 / 改了指标口径 | ⚠️ 同上 |
| 什么都没做，只是重开电脑 | ✅ 数据仍然有效（静态文件，不依赖集群） |

**怎么一眼判断"这份图是什么时候的"**：

```bash
# 看数据文件里的生成时间
head -3 "D:\数据开发\项目产出\可视化\dashboard_data_real.js"
# 找 "generated_at": "2026-10-04 11:04:26"
```

页面上**右上角也显示了"数据导出时间"和"数据区间"** —— 这是故意做的，**避免把旧图当新数看**。

> 💡 **好习惯**：演示/答辩前一天，重跑一次导出，让 `generated_at` 是当天的。

## 三、想改东西时，改哪个文件（对照表）

**这条流水线是"生成物"结构，改错地方等于白改。**

```
   ①  主数据源：Hive 表（集群上的 gmall 库）
        │
        │  ②  export_dashboard_real.sh  ← 想改"取哪些数据/取哪些列" 改这里
        ▼
   ③  CSV（生成物，在集群 /home/lrh/workspace/new_chain/dashboard_real/raw/）
        │      ⛔ 不要手工改 CSV —— 下次导出会覆盖
        │  ④  csv2json_real.py  ← 想改"字段名/类型/取整/新增数据集" 改这里
        ▼
   ⑤  dashboard_data_real.js（生成物）  ⛔ 不要手工改 —— 下次转换会覆盖
        │
        │  ⑥  dashboard_real.html  ← 想改"图画成什么样/加一张图" 改这里
        ▼
   ⑦  屏幕
```

| 你想改什么 | 改哪个文件 | 改完要做什么 |
|---|---|---|
| 取哪些表 / 哪些列 / 加筛选条件 | `export_dashboard_real.sh` 里的 SQL | 重跑整条流水线（第 ①②③ 步） |
| 列的字段名、数值取整、新增一个数据集 | `csv2json_real.py` 的 `SPEC` / `NUMERIC` / `ROUND` | **只需重跑第 ④ 步**（CSV 已在集群上，3 秒） |
| 加一张图、改配色、改口径说明文字 | `dashboard_real.html` | 刷新页面即可 |
| 改"数据的业务口径"（比如复购率算法） | ⚠️ **要改的是 Hive 的 ETL SQL**（`evt_etl.sql`），然后重跑 ETL，再重跑本流水线 | 整条链路 |

**重跑第 ④ 步（只重新生成 JS，不重新查 Hive）**：

```bash
cd /home/lrh/workspace && python3 csv2json_real.py /home/lrh/workspace/new_chain/dashboard_real
```

> ⚠️ **两处必须同步改的"隐式契约"**：
> `export_dashboard_real.sh` 里 `SELECT` 的**列顺序**，必须与 `csv2json_real.py` 里 `SPEC` 的**列名顺序**一致。
> **CSV 是按位置取值的，不是按列名。** 只调换 SQL 里两列的顺序而不改脚本 → **数据整体错位，而且不报错**。
> （两个文件里都留了这句注释提醒。）

## 四、★ 对账：怎么证明"数据没错"

**别相信脚本打印的"完成"。** 导出成功只说明它跑完了，不说明它跑对了。做法是**从交付物反向重算**：

```bash
# 在 lrh-1 上：从生成好的 CSV 重算汇总
python3 - <<'PY'
import csv
def load(p):
    with open('/home/lrh/workspace/new_chain/dashboard_real/raw/'+p, newline='') as f:
        return list(csv.DictReader(f))
td = load('trade_day.csv'); cat = load('category.csv'); d = load('dau.csv'); f = load('funnel.csv')
print("天数            =", len(td))
print("GMV 合计        = %.2f" % sum(float(r['gmv']) for r in td))
print("成交笔数合计    = %d" % sum(int(r['order_cnt']) for r in td))
print("DAU 均值        = %.0f" % (sum(int(r['dau']) for r in d)/len(d)))
print("new_dau>0 天数  =", sum(1 for r in d if int(r['new_dau'])>0), "/", len(d))
print("购买>加购 天数  =", sum(1 for r in f if int(r['purchase_uv'])>int(r['cart_uv'])), "/", len(f))
PY

# 再和 Hive 直接查对账（四路 GMV 必须完全相同）
/opt/hive/apache-hive-3.1.3-bin/bin/beeline -u jdbc:hive2://lrh-1:10000 --silent=true --outputformat=csv2 -e "
select 'trade_day' k, round(sum(gmv),2) v from gmall.dws_trade_day
union all select 'category', round(sum(gmv),2) from gmall.dws_category_event_day
union all select 'product',  round(sum(gmv),2) from gmall.dws_product_event_day
union all select 'dwd_fact', round(sum(amount),2) from gmall.dwd_purchase_fact_di;" 2>/dev/null | grep -a GMV
```

**2026-10-04 的实测基准（下次导出应该一模一样，除非 ETL 数据变了）**：

| 指标 | 基准值 |
|---|---|
| 天数 | **31**（2019-10-01 ~ 2019-10-31） |
| GMV 合计 | **57,575,996.50**（= Hive 的 `5.75759965E7`，四路一致） |
| 成交笔数合计 | **186,059**（= `dwd_purchase_fact_di` 行数） |
| 日均 DAU | **52,349** |
| 客单价（加权，卡片显示值） | **309.45**（= `Σgmv ÷ Σorder_cnt`，与卡片下方说明"成交金额 ÷ 成交笔数"一致） |
| 客单价（逐日值再平均） | 309.68 ⚠️ **这个数不对，别当基准**——"平均的平均"，见下方说明 |
| new_dau > 0 的天数 | **31 / 31** |
| wakeup_dau > 0 的天数 | **29 / 31** |
| 购买 > 加购 的天数 | **15 / 31**（真实业务现象，不是错） |
| 数据行数 | dau/funnel/repurchase/trade_day 各 31；top_product 15；category 12 |

> ⚠️ **`category` 是 Top12**（SQL 里 `LIMIT 12`），所以它的 GMV 合计会**略小于**总额（实测差约 0.008%）。
> 这是"构成图只展示前 12 名"的正常结果，**不是 bug**。

> ⚠️ **2026-10-18 修正：客单价卡片原来显示 `309.68`，是错的，已改成 `309.45`。**
>
> 原因是大屏用 `avg(trade, 'avg_order_amount')` —— 把**31 天的每日客单价再做了一次平均**。
> 而卡片底下自己写着"成交金额 ÷ 成交笔数"，正确算法是 `Σgmv ÷ Σorder_cnt`。
>
> | 算法 | 结果 | 对不对 |
> |---|---|---|
> | `Σgmv ÷ Σorder_cnt` = 57,575,996.50 ÷ 186,059 | **309.45** | ✅ 加权，正确定义 |
> | `avg(每日客单价)` | 309.68 | ❌ "平均的平均"——把订单少的那些天和订单多的那些天**平等对待**了 |
>
> 这就是数据建模里那条铁律：**`AVG` 不可加，聚合之后再平均就失真**。
> 只有两天时它俩相等；天数越多、每天单量差异越大，偏差越大（本例差 0.23 元）。
>
> 与它同源的还有一处**已经在文档里被警告过**（`零基础教程/07` L322）："客单价 = GMV / 单量，
> **不能**对各城市的客单价再求平均"。同一个坑，建模文档记得、大屏代码没记住。
> **教训：坑写进教材不等于坑被防住——要落到代码里（这次直接写成 `sum(gmv)/sum(order_cnt)`）。**
>
> 顺带说明：`dashboard_data_real.js` 里的 `avg_order_amount` 字段**每天的值都是对的**（31/31 与 `gmv/order_cnt` 逐日吻合），
> 所以"成交趋势"图的客单价曲线**没有问题**——错的只是把 31 个正确值又平均了一次的那个 KPI。

## 五、集群没开时，怎么验证（离线自检）

**这是本次学到的一个实用招**：大屏是**纯前端 + 一个数据文件**，所以**数据之外的部分完全不依赖集群**。

思路：**造一份"形状正确"的测试数据**（列名/列序和导出 SQL 一模一样，内容随便填），
跑一遍转换脚本，检查**产出的字段是不是页面要读的那些、类型对不对**。

> 下面用 PowerShell 写（本机可直接跑）。**关键点：测试数据放在临时目录，绝不放进项目目录** ——
> 免得把"假数据"混进交付物（本项目纪律：**错误的数据比没有数据更危险**）。

```powershell
# ① 造一份 3 天的测试 CSV（列名/列序必须与 export_dashboard_real.sh 的 SELECT 完全一致）
$fx = "$env:TEMP\dashfix"
Remove-Item $fx -Recurse -Force -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force "$fx\raw" | Out-Null

# 只造其中一个数据集就够验证"转换是否正常"；要全量验证就 6 个都造
@"
dt,dau,new_dau,active_dau,wakeup_dau
2019-10-01,41230,12000,18000,11230
2019-10-02,39877,9000,20000,10877
"@ | Set-Content "$fx\raw\dau.csv" -Encoding utf8
# ... 其余 5 个数据集（funnel / repurchase / top_product / trade_day / category）同理 ...

# ② 跑转换（把 python 换成你机器上的 python 路径）
python "D:\数据开发\项目产出\可视化\csv2json_real.py" $fx
# → 生成 $fx\dashboard_data_real.js；打开看 6 个数据集的字段齐不齐
```

```powershell
# ③ 把 html 里的内联 JS 抽出来做语法检查（不需要浏览器、不需要集群）
$html = Get-Content "D:\数据开发\项目产出\可视化\dashboard_real.html" -Raw
$js = [regex]::Matches($html, '(?s)<script>(.*?)</script>') | ForEach-Object { $_.Groups[1].Value }
Set-Content "$env:TEMP\_check.js" ($js -join "`n") -Encoding utf8
node --check "$env:TEMP\_check.js"     # 没输出 = 语法通过
```

**④ 检查"该是数字的字段，类型是不是真的数字"** —— 用 Python 读一下生成的 JSON：

```python
import json
txt = open(r"C:\...\dashboard_data_real.js", encoding="utf-8").read()
D = json.loads(txt.split("=", 1)[1].rstrip().rstrip(";"))
for k in ("dau", "funnel", "trade_day"):
    row = D[k][0]
    print(k, {f: type(v).__name__ for f, v in row.items()})
# 期望数值字段是 int / float；如果是 str，说明 NUMERIC 表漏了这一列
```

> 💡 这套"离线自检"的价值：**在花集群时间之前，就把代码层的错抓出来。**
> 本次顺序就是"先离线自检通过 → 再上集群导真数据"，**一次成功**。

## 六、回滚：怎么退回旧版大屏

**本项目是"两版并存"，所以回滚不需要任何操作** —— 旧版从来没被动过：

| 你想看 | 打开这个文件 |
|---|---|
| **真实数据版**（新版） | `项目产出/可视化/dashboard_real.html` |
| **模拟数据版**（旧版） | `项目产出/可视化/dashboard.html` |

**如果要让某一版成为"主大屏"**（比如答辩就用真实数据版）：

```powershell
cd "D:\数据开发\项目产出\可视化"
# 先把旧版留个备份名，再把新版扶正
Move-Item dashboard.html      dashboard_mock.html            # 旧版改名留档
Move-Item dashboard_data.js   dashboard_data_mock.js
Copy-Item dashboard_real.html dashboard.html                 # 新版扶正
Copy-Item dashboard_data_real.js dashboard_data.js
```

> ⚠️ **注意**：`dashboard.html` 里 `<script src="./dashboard_data.js">` 是**写死的文件名**。
> 所以"扶正"时必须**同时**把 `dashboard_data_real.js` 拷成 `dashboard_data.js`，否则页面白屏。
> 或者改 html 里那一行 `src`。

**彻底回滚（放弃新版）**：把 `dashboard_real.html` 和 `dashboard_data_real.js` 删掉即可，旧版不受影响。

## 七、常见问题

**Q1：页面打开是空白的，只有一句"数据文件未加载"。**
A：`dashboard_real.html` 和 `dashboard_data_real.js` **必须放在同一个文件夹**（页面用相对路径 `./` 引用）。
另外确认 `echarts.min.js` 也在同一目录。这三个文件缺一不可。

**Q2：图出来了，但某一张图是空的。**
A：多半是**那个数据集的 CSV 是空的**。去集群看 `dashboard_real/raw/<名字>.csv` 有几行。
常见原因：对应的 Hive 表是空的（比如 ETL 没跑完、或表被 `DROP` 重建过）。

**Q3：导出脚本报错 `Table not found: gmall.xxx`。**
A：ETL 还没跑，表不存在。**先跑一遍数仓 ETL**（`dwd_run.sh` + `evt_run.sh`，或用 DolphinScheduler 工作流），
再回来导大屏。

**Q4：导出的金额是一长串小数（`...000000006`）。**
A：说明 `csv2json_real.py` 里的 `ROUND` 表没生效或漏了字段。检查 `ROUND = {"gmv": 2, ...}` 里有没有这个列名。

**Q5：X 轴日期挤成一团。**
A：`dashboard_real.html` 里 `axisLabel: { interval: 4 }` 的数字调大（每隔几个显示一个）。

**Q6：漏斗图顺序看着不对。**
A：确认漏斗的 `series` 里有 **`sort: 'none'`**。
真实数据里"购买 > 加购"是常态（实测 15/31 天），ECharts 默认会按数值降序重排，把顺序画反。

**Q7：我在页面上看到的数和 Hive 里查的不一样。**
A：先看数据文件的 `generated_at` —— **大概率是数据过期了**（ETL 之后没重新导出）。跑第五章的对账脚本确认。
