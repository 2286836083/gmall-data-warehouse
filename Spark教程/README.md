> **这套文档给谁看**：已经知道"Hive 能写 SQL 算数据"，但搞不清 **Spark 是什么、快在哪、什么时候该用**的人。

> 建立日期：2026-10-11 ｜ 全部结论来自本项目实测（实验 10）· 环境：三节点 VMware 集群

## 一、为什么还要学 Spark（一句话）

**因为"只会 Hive"在面试里是个明显短板** —— 面试官几乎必问
"Spark 和 Hive 有什么区别、你会怎么选"。

而更现实的原因是：**Spark 已经是大数据计算的主流**，很多公司的数仓 ETL 跑在 Spark 上。
你不需要成为 Spark 专家，但必须能回答三个问题：

1. Spark 到底是什么（它和 Hive 是什么关系）？
2. 它为什么比 MapReduce 快？（以及**在什么情况下它反而不快**）
3. 我的这条 ETL，该用 Hive 还是 Spark？

> ⚠️ **提前打个预防针**：第 2 个问题的答案**不是"Spark 快 5 倍"**。
> 本项目实测下来，结论要分情况，而且**有一半和流行说法相反**。
> 这正是本项目最值钱的结论之一 —— 详见第 05 篇。

| 你需要先懂                               | 在哪学                                                      |
| ---------------------------------------- | ----------------------------------------------------------- |
| **MapReduce 和 YARN 是怎么干活的** | `零基础教程/05_计算_YARN与MapReduce.md` ⭐ **必读** |
| Hive 是什么、表和分区是什么              | `零基础教程/06_SQL_Hive与HQL.md` ⭐ **必读**        |
| 数仓分层怎么设计                         | `零基础教程/07`、`08`（看第 05 篇的对比结论时需要）     |

**为什么必须先读 05**：Spark 是"**另一种计算引擎**"——它替换的是 MapReduce 的位置。
如果你不知道 MapReduce 是怎么把活干完的（map → shuffle → reduce、中间结果落盘、每个任务起一个 JVM），
你就**理解不了 Spark 到底优化了什么**，只能死记"Spark 快因为用内存"这种半懂的话。

> 📌 **一句话衔接**：05 篇讲的是"**活是怎么被干完的（MapReduce 版）**"，
> 这套文档讲的是"**同一个活，换一种干法（Spark 版），差别在哪**"。

## 六、先给你三句结论（读之前先有个底）

1. **Spark 和 Hive 不是竞争关系**。Hive 管"表长什么样 + 把 SQL 翻译成任务"，
   Spark 管"把任务算出来"。**本项目的 Spark 用的就是 Hive 的元数据**，两者共用同一批表定义。
2. **Spark 快的原因，主流说法只说对了一半**。中间结果不落盘、Executor 常驻确实有效，
   但本项目实测发现：**它的收益几乎全部来自"会话复用"**——同一个会话里连跑 8 段 SQL 快 5 倍，
   每段各起一个会话就只快 10%，轻作业上甚至更慢。
3. **单条短查询永远别用 Spark**。一次提交的固定开销约 **35 秒**（启动 JVM、连元数据、向 YARN 申请资源），
   比很多查询本身的执行时间还长。
