## 一、名词对照表

### 1.1 角色类（谁是谁）

| 英文 | 中文 | 一句话解释 | 物理上是什么 |
|---|---|---|---|
| **Driver** | 驱动器 | 应用的"大脑"：解析 SQL、生成计划、切分任务、派活、收结果 | 一个 JVM 进程（本项目在 lrh-1） |
| **Executor** | 执行器 | 真正干活的"工人"：读数据、算、写结果，**内部用线程跑任务** | 一个 JVM 进程，跑在 YARN 容器里、**常驻** |
| **ApplicationMaster (AM)** | 应用管理器 | **YARN 那边的项目经理**：向 YARN 申请 Executor 容器 | 一个独立 JVM 进程 |
| **SparkSession** | 会话 | 你操作 Spark 的"入口对象"（创建表、执行 SQL 都得通过它） | Driver 里的一个 Java 对象 |
| **SparkContext** | 上下文 | 老版本的名字，现在被 SparkSession 包在里面了 | 同上 |
| **Master / Worker** | 主 / 从 | 只在 **standalone**（Spark 自带集群模式）下才有；本项目跑在 YARN 上，**用不到** | —— |

### 1.2 任务层级类（★ 最容易混）

| 英文 | 中文 | 粒度 | 一句话解释 |
|---|---|---|---|
| **Application** | 应用 | 最大 | 你提交的一次"活"（比如跑完这 8 条 SQL） |
| **Job** | 作业 | ↓ | **一条 SQL / 一个"动作"触发的全部计算** |
| **Stage** | 阶段 | ↓ | Job 内部按"要不要跨机器搬数据"切开的段 |
| **Task** | 任务 | 最小 | Stage 内部并行的最小单位，**是线程不是进程** |

**包含关系**：应用 ⊃ 作业 ⊃ 阶段 ⊃ 任务

### 1.3 数据抽象类

| 英文 | 中文 | 一句话解释 |
|---|---|---|
| **RDD** | 弹性分布式数据集 | 一批可分片的数据，**记得自己是怎么算出来的**（丢一片能重算） |
| **DataFrame** | 数据框 | **带列名的二维表**（像 Excel），可直接用 SQL 查 —— 本项目主要用它 |
| **DataSet** | 数据集 | DataFrame 的"强类型版"，主要在 Scala/Java 里用；Python 里没有 |
| **Partition** | 分片 | 数据的**并行份数**（几片 = 几个任务并行）⚠️ 和 Hive 的"分区"不是一回事 |
| **Broadcast** | 广播变量 | 把一份小数据**发给每个执行器各存一份**，避免反复传输（大表关联小表时用） |

### 1.4 操作与机制类

| 英文 | 中文 | 一句话解释 |
|---|---|---|
| **Transformation** | 转换 | 描述一个加工步骤（过滤、分组…），**惰性，不立刻执行** |
| **Action** | 动作 | 要结果（`count`/`show`/`write`），**才真正触发计算** |
| **DAG** | 有向无环图 | "带先后顺序的施工进度图"，Spark 用它描述整个计算流程 |
| **Shuffle** | 洗牌 / 数据重分布 | 把同类数据搬到同一台机器上。**最贵的操作**，也是 Stage 的分界线 |
| **Exchange** | 交换 | 执行计划里看到这个词 = **这里有一次 shuffle** |
| **Catalyst** | 催化剂 | Spark SQL 内部的**查询优化器**（改写、化简你的 SQL） |
| **AQE** | 自适应查询执行 | Spark 3 的能力：**边跑边看实际数据量，动态调整计划** |
| **数据倾斜** | —— | 某个 key 数据特别多，导致一个任务拖慢整个阶段 |
| **JVM** | Java 虚拟机 | 运行 Java 程序的"容器"（本质是一个进程）；**反复启动它很贵** |
| **JIT** | 即时编译 | JVM 把热点代码编译成机器码，**越跑越快**——解释"为什么单会话连跑逐段变快" |
| **OOM** | 内存溢出 | 内存不够导致崩溃（分"堆内不够"和"容器超限"两种） |
| **Thrift** | —— | 一种"跨语言远程调用协议"，可以理解为**客户端和服务端的通话格式** |

### 1.5 容易混的两组词（单独拎出来）

| 容易混 | 区别 |
|---|---|
| **Driver vs Executor** | 一个是**脑**（决定怎么算），一个是**手**（真算）。Driver 挂了应用就挂 |
| **Executor vs Task** | Executor 是**进程**（常驻、少而大），Task 是它内部的**线程**（临时、多而小） |
| **Job vs Stage** | Job 是"一次完整计算"，Stage 是它内部被 shuffle 切开的段落 |
| **Spark 的 partition vs Hive 的 partition** | Spark = **并行份数**；Hive = **目录**（`dt=2019-10-01/`） |
| **Driver vs ApplicationMaster** | Driver 管**计算**；AM 管**资源申请**（client 模式下两者是分开的） |

## 二、命令速查

```bash
SP=/opt/spark-3.5.9-bin-hadoop3/bin/spark-sql

# ── 跑 SQL ──
$SP -e "SELECT COUNT(1) FROM gmall.ods_event_log_di;"      # 单条（每次付 35 秒）
$SP -f all_steps.sql                                       # ★ 多段拼一个文件，一个会话跑完

# ── 提交应用（写代码的作业）──
/opt/spark-3.5.9-bin-hadoop3/bin/spark-submit \
  --master yarn --deploy-mode client \
  --executor-memory 1408m --executor-cores 2 --num-executors 3 \
  my_job.py

# ── 看作业 ──
# Spark UI（应用运行时）：  http://lrh-1:4040
# YARN 侧（看应用）：       http://lrh-1:8088  或  yarn application -list

# ── HDFS 上的 Spark 资产 ──
hdfs dfs -ls /spark/jars/            # jar 分发目录（252 个文件 / 338MB）
hdfs dfs -ls /spark/eventlogs/       # 事件日志（给 History Server 回放用）
```

## 三、配置速查（本项目实况，可直接抄）

```properties
# ── 跑在 YARN 上，Driver 在本地（client 模式）──
spark.master                              yarn
spark.submit.deployMode                   client

# ── 连 Hive 元数据（版本必须与集群 metastore 一致）──
spark.sql.hive.metastore.version          3.1.3
spark.sql.hive.metastore.jars             path
spark.sql.hive.metastore.jars.path        file:///opt/hive/apache-hive-3.1.3-bin/lib/*

# ── ★ 写分区表必须 dynamic，否则会清空整表 ──
spark.sql.sources.partitionOverwriteMode  dynamic

# ── 资源（每个数都被 YARN 上限 2048MB 逼出来）──
spark.executor.memory                     1408m
spark.executor.memoryOverhead              384m     # 1408+384=1792 ≤ 2048
spark.executor.cores                         2
spark.executor.instances                     3
spark.driver.memory                         1g

# ── 并行度（默认 200 在 6 核集群上是灾难）──
spark.sql.shuffle.partitions                 6

# ── jar 走 HDFS，免每次重传 338MB ──
spark.yarn.jars                    hdfs://lrh-1:8020/spark/jars/*
spark.eventLog.enabled                    true
spark.eventLog.dir                hdfs://lrh-1:8020/spark/eventlogs
```

## 四、Hive / Spark 差异速查

| 项目 | Hive | Spark | 要注意什么 |
|---|---|---|---|
| `INSERT OVERWRITE` 分区表 | 只覆盖涉及的分区 | **默认清空整表** | ★ 必须设 `partitionOverwriteMode=dynamic` |
| `sequence()` 造序列 | ❌ 没有 | ✅ 有 | Hive 用 `posexplode(split(repeat(',',N),','))` |
| `dayofweek()` | 1 = 星期日 | 与 Hive 不同 | 做星期维度**必须单独验证** |
| 类型严格程度 | 宽松（隐式转换多） | 更严格 | 显式 `CAST` 最安全 |
| 内存参数 | 容器 + `-Xmx` | Executor 内存 + 堆外开销 | 都受 YARN 容器上限约束 |
| 并行度参数 | `mapreduce.job.reduces` | `spark.sql.shuffle.partitions` | Spark 默认 200，小集群务必改 |
| 启动开销 | 每个作业几秒（占比小） | **每次会话约 35 秒** | 决定"什么时候该用 Spark" |

## 五、报错速查

| 报错 / 现象 | 根因 | 怎么办 |
|---|---|---|
| `Invalid method name` / 连不上 metastore | Spark 内置 Hive 客户端（2.3.9）与集群 metastore（3.1.3）版本不匹配 | 配 `metastore.version=3.1.3` + `jars=path` |
| 补跑单日，其他分区消失（**不报错**） | `partitionOverwriteMode` 是默认的 `STATIC` | 设成 `dynamic` |
| `Error 10011 Invalid function sequence` | 在 **Hive** 里用了 Spark 的函数 | 换 Hive 写法 |
| `OutOfMemoryError: Java heap space` | 堆内存不够 | 调大 `executor.memory`（注意总和 ≤ 2048） |
| `Container killed ... exceeding memory limits` | 容器总额度超了（堆内+堆外） | 调大 `memoryOverhead` 或减小堆内存 |
| `TTransportException: Cannot write to null outputStream` | Spark 初始化时切换授权组件导致的连接重建；**良性** | 判断三件事：异常在哪条路径、是否自动重试成功、结果是否与基线一致 |
| 几百个 task 各处理几十 KB | `shuffle.partitions` 没改（默认 200） | 调成 `总核数 × 1~2` |
| 个别 task 跑特别久 | 数据倾斜 | 过滤异常 key / 两阶段聚合 / 广播小表 |
| 作业一直不开始、等很久 | YARN 资源被占满 | `yarn application -list` 看是谁占着；`-kill` 掉 |
| SQL 写完了但"什么都没发生" | 只写了 Transformation，**没有 Action** | 加一个 `count()` / `write` 之类 |
