# 03 · 从零搭一套三节点集群

> **这章解决什么**：从"一台空虚拟机"到"`hdfs dfsadmin -report` 显示 3 个 DataNode 在线、YARN 有 3 个 NodeManager"。
> 这是全课程第一个**硬里程碑**——后面的所有东西都跑在它上面。
>
> **预计耗时**：第一次 2~4 小时（大部分花在下载和 VMware 安装上）。
> 如果卡住，**90% 的问题在"SSH 免密"和"配置文件写错"这两处**。

---

## 一、开工前：先决定几台机器、怎么分资源

### 1.1 三台的职责分配（案例集群的真实分工）

| 主机名 | IP | 内存 | 跑什么进程 |
|---|---|---|---|
| **lrh-1**（主） | 192.168.87.131 | **7168MB** | NameNode、SecondaryNameNode、DataNode、ResourceManager、NodeManager、ZooKeeper、MySQL、Hive MetaStore、HiveServer2、DS master/api |
| **lrh-2**（从） | 192.168.87.130 | 3392MB | DataNode、NodeManager、ZooKeeper、DS worker |
| **lrh-3**（从） | 192.168.87.132 | 4096MB | DataNode、NodeManager、ZooKeeper、DS worker |

**为什么不是平均分**：主节点要跑 9 个 Java 进程，从节点只跑 4 个。
平均分的结果是主节点可用内存只剩 601MB 并开始 swap（把内存换到硬盘，慢几十倍），
而从节点还闲着 2GB。**按负载分配，不按人头分配。**

> 💡 你的机器内存不够怎么办？**开一台伪分布式（单机同时当主和从）也能学完 90% 的内容**，
> 只是看不到"多机器协作"的现象。把下文所有"三台"理解成"一台也行"，命令大部分通用。

### 1.2 版本选择（别追新）

| 组件 | 案例集群 | 选择原则 |
|---|---|---|
| Ubuntu | 24.04 Desktop | 用 Server 版也行；**桌面版记得关图形界面省内存** |
| JDK | **8**（`jdk1.8.0_202`） | Hadoop 3.x 生态的事实标准 |
| Hadoop | 3.3.6 | 稳定、资料多 |
| Hive | 3.1.3 | 与 Hadoop 3.3 常配组合 |
| Spark | 3.5.9 | **JDK 8 支持的最后一条主线**（4.x 要 JDK 17+） |

> ⚠️ **版本不是越新越好**。新版本可能：要更高的 JDK、改默认行为（Spark 3 起默认 ANSI 模式会改 SQL 语义）、
> 资料少到出问题搜不到。**学习阶段优先选"出问题能搜到答案"的版本。**

## 二、第一步：创建虚拟机（这里有真坑）

### 2.1 基本流程

VMware Workstation → 新建虚拟机 → 典型/自定义 → 选 ISO → 分配 CPU/内存/磁盘 → 完成。

### 2.2 ⚠️ 坑：不要用 VMware 的"简易安装"（Easy Install）

这是案例项目**真实踩过两次**的坑，浪费了一整个下午：

**现象**：明明在安装界面填了用户名 `lrh`，装完进系统，终端提示符却是 `ubuntu@ubuntu`，用户名完全不对。

**根因（物理层面）**：VMware 的 Easy Install 会临时生成一个 `autoinst.iso` 挂到虚拟机上，
里面写死了默认用户 `ubuntu`，**它会覆盖你在安装界面填的内容**。
而且它只对 Server 版 ISO 有效，对 Desktop 版 ISO 支持不好（曾出现虚拟磁盘只有 3.5MB 的诡异情况）。

**解法**：

1. 新建虚拟机时选 **"稍后安装操作系统"**（不要让它自动装）
2. 建好后去虚拟机设置里，**删掉自动挂载的 `autoinst.iso` 光驱和软驱**
3. 再手动挂载 Ubuntu ISO 启动安装

### 2.3 安装界面上最关键的一页

安装到 **"Who are you"（你是谁）** 这一页，注意区分三个框：

| 框 | 填什么 | 说明 |
|---|---|---|
| Your name | 你的名字 | 显示用的全名 |
| **Your computer's name** | **主机名**，建议 `lrh-1` | ⚠️ 这个决定了终端提示符后面的部分 |
| **Pick a username** | **用户名**，建议 `lrh` | ⚠️ 这个决定了 `whoami` 的结果和家目录名 |

> 📌 **本项目对照**：案例集群三台的用户名都是 `lrh`，主机名分别是 `lrh-1/2/3`。
> 所以登录后提示符是 `lrh@lrh-1:~$`。
> 如果你装完发现是 `ubuntu@ubuntu`，说明你进的是 **Live 试用会话**，不是装好的系统——重启并断开 ISO 后再看。

### 2.4 装完立刻做的三件事

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y openssh-server net-tools vim curl wget
sudo systemctl enable --now ssh          # 开 SSH，否则你只能对着 VMware 窗口敲命令
```

> 之后所有操作都在你自己的终端里 `ssh` 进去做，**别再在虚拟机窗口里操作**（不能复制粘贴、滚动条难用）。

## 三、第二步：网络——让三台机器互相找得到

### 3.1 每台机器设静态 IP

VMware 用 NAT 模式时，IP 由 VMware 的 DHCP 分配，**重启可能变**。
集群最怕 IP 变（配置文件里写的是主机名，但主机名靠 `/etc/hosts` 解析到 IP，IP 一变全断）。

Ubuntu 24.04 用 netplan：

```bash
sudo vim /etc/netplan/01-netcfg.yaml
```

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:                       # ⚠️ 网卡名用 ip a 查，可能是 ens33 / ens160 / eth0
      dhcp4: no
      addresses: [192.168.87.131/24]
      routes:
        - to: default
          via: 192.168.87.2      # 网关：VMware NAT 通常是 .2
      nameservers:
        addresses: [8.8.8.8, 114.114.114.114]
```

```bash
sudo netplan apply
ip a | grep inet                 # 确认 IP 生效
ping 192.168.87.2                # 能通网关
```

### 3.2 三台都写 /etc/hosts（**集群的命根子**）

```bash
sudo vim /etc/hosts
```

```
192.168.87.131  lrh-1
192.168.87.130  lrh-2
192.168.87.132  lrh-3
```

```bash
ping -c 2 lrh-2        # 用主机名能通，才算配好
```

> ⚠️ **不要留 `127.0.1.1 lrh-1` 这类回环解析**。Hadoop 组件靠主机名互相连，
> 一旦解析到 127.0.0.1，会出现"进程起来了但连不上"的诡异现象。

### 3.3 配 SSH 免密（**这一步没做，Hadoop 起不来**）

**为什么必须**：主节点启动 Hadoop 时，会通过 SSH 登录到从节点去拉起 DataNode / NodeManager 进程。
没有免密，就是卡在"等待输入密码"，然后静默失败。

**那为什么连"自己对自己"也要免密？**
因为 `start-dfs.sh` 实际做的是：读 `workers` 列表（里面**包含 lrh-1 自己**）→
对着列表里**每一个主机名**执行一次 `ssh <主机> 启动对应进程`。
轮到 `lrh-1` 那一行时，它同样要走一次 SSH —— **本机 SSH 也要过认证这一关**。
漏掉 `ssh-copy-id lrh@lrh-1`，现象就是脚本卡在"启动本地 NameNode"那一步不动。

```bash
# 在 lrh-1 上执行（用 lrh 用户，不要用 root）
ssh-keygen -t ed25519                       # 一路回车
ssh-copy-id lrh@lrh-1                       # ★ 自己也要免密（很多教程漏了这条）
ssh-copy-id lrh@lrh-2
ssh-copy-id lrh@lrh-3

ssh lrh@lrh-2 hostname                      # 测试：应该直接返回 lrh-2，不输密码
```

> 失败排查：`chmod 700 ~/.ssh`、`chmod 600 ~/.ssh/authorized_keys`、`sudo tail -50 /var/log/auth.log`

## 五、第四步：装 Hadoop（先装一台，再分发）

### 5.1 解压

```bash
sudo tar -zxvf hadoop-3.3.6.tar.gz -C /opt/hadoop/
sudo vim /etc/profile.d/hadoop.sh
```

```bash
export HADOOP_HOME=/opt/hadoop/hadoop-3.3.6
export HADOOP_CONF_DIR=/opt/hadoop/hadoop-3.3.6/etc/hadoop
export PATH=$PATH:$HADOOP_HOME/bin:$HADOOP_HOME/sbin
```

### 5.2 四个核心配置文件（**照抄可跑**）

配置目录：`/opt/hadoop/hadoop-3.3.6/etc/hadoop/`

#### ① `hadoop-env.sh` —— 写死 JAVA_HOME

```bash
export JAVA_HOME=/opt/jdk/jdk1.8.0_202
```

> 为什么必须在文件里写死：启动脚本是独立进程，不继承你在命令行设的环境变量。

#### ② `core-site.xml` —— 全局入口

```xml
<configuration>
    <property>
        <name>fs.defaultFS</name>
        <value>hdfs://lrh-1:8020</value>      <!-- HDFS 的总入口 -->
    </property>
    <property>
        <name>hadoop.tmp.dir</name>
        <value>/opt/hadoop/tmp</value>        <!-- 各种临时数据落在这 -->
    </property>
</configuration>
```

> 📌 案例集群还配了 `hadoop.proxyuser.lrh.hosts=*`（允许代理用户，Hive 用到）。

#### ③ `hdfs-site.xml` —— 存储相关

```xml
<configuration>
    <property>
        <name>dfs.replication</name>
        <value>3</value>                       <!-- 每份数据存几份 -->
    </property>
    <property>
        <name>dfs.namenode.name.dir</name>
        <value>${hadoop.tmp.dir}/dfs/name</value>
    </property>
    <property>
        <name>dfs.datanode.data.dir</name>
        <value>${hadoop.tmp.dir}/dfs/data</value>   <!-- 真正的数据块落在这 -->
    </property>
    <property>
        <name>dfs.permissions.enabled</name>
        <value>false</value>                   <!-- 学习环境关掉权限检查，省很多麻烦 -->
    </property>
</configuration>
```

#### ④ `yarn-site.xml` —— 计算调度

```xml
<configuration>
    <property>
        <name>yarn.resourcemanager.hostname</name>
        <value>lrh-1</value>
    </property>
    <property>
        <name>yarn.nodemanager.aux-services</name>
        <value>mapreduce_shuffle</value>        <!-- ★ 必须开，否则 reduce 拉不到数据 -->
    </property>
    <property>
        <name>yarn.nodemanager.resource.memory-mb</name>
        <value>2048</value>                     <!-- 这台机器愿意拿出多少内存给计算 -->
    </property>
    <property>
        <name>yarn.nodemanager.vmem-check-enabled</name>
        <value>false</value>                    <!-- 虚拟内存检查在虚拟机上经常误杀任务 -->
    </property>
</configuration>
```

> 📌 **本项目对照**：`2048` 是案例集群的真实值，也是**最硬的一条约束**——
> YARN 每节点只有 2GB，单容器上限就是 2GB。后面 Hive 和 Spark 的所有内存参数都被这个数卡死（第 11 章）。

#### ⑤ `mapred-site.xml` —— 计算框架

```xml
<configuration>
    <property>
        <name>mapreduce.framework.name</name>
        <value>yarn</value>                     <!-- 用 YARN 调度，不是本地跑 -->
    </property>
    <property>
        <name>yarn.app.mapreduce.am.env</name>
        <value>HADOOP_MAPRED_HOME=/opt/hadoop/hadoop-3.3.6</value>
    </property>
    <property>
        <name>mapreduce.map.env</name>
        <value>HADOOP_MAPRED_HOME=/opt/hadoop/hadoop-3.3.6</value>
    </property>
    <property>
        <name>mapreduce.reduce.env</name>
        <value>HADOOP_MAPRED_HOME=/opt/hadoop/hadoop-3.3.6</value>
    </property>
</configuration>
```

> 那三行 `HADOOP_MAPRED_HOME` 是 Hadoop 3.x 的**必填项**，不写会报
> `Could not find or load main class org.apache.hadoop.mapreduce.v2.app.MRAppMaster`。

#### ⑥ `workers` —— 有哪些从节点

```
lrh-1
lrh-2
lrh-3
```

> 一行一个主机名。**文件名在 Hadoop 2.x 叫 `slaves`**，老教程里是这个名字。

### 5.3 分发到另外两台

**最省事的做法：先在一台配好，再整体拷贝。**

```bash
# 在 lrh-1 上
sudo tar -czf /tmp/hadoop.tgz -C /opt/hadoop hadoop-3.3.6
scp /tmp/hadoop.tgz lrh@lrh-2:/tmp/ && scp /tmp/hadoop.tgz lrh@lrh-3:/tmp/
scp /etc/profile.d/hadoop.sh lrh@lrh-2:/tmp/ && scp /etc/profile.d/hadoop.sh lrh@lrh-3:/tmp/

# 在 lrh-2、lrh-3 上
sudo tar -xzf /tmp/hadoop.tgz -C /opt/hadoop/
sudo cp /tmp/hadoop.sh /etc/profile.d/
source /etc/profile
```

> **为什么推荐整体拷贝而不是在每台机器上改一遍**：
> 三台配置必须**完全一致**。手工改三遍，一定会有一处不一致，而那个不一致会以最离奇的方式报错。

## 六、第五步：格式化 + 启动

### 6.1 格式化 NameNode（**只在第一次做一次**）

```bash
hdfs namenode -format
```

> ⚠️ **这条命令不要重复执行**。它会**清空** HDFS 上所有数据和元数据。
> 重复格式化的典型后果：DataNode 的集群 ID 和 NameNode 对不上，**DataNode 起不来**，
> 表现是 `dfsadmin -report` 里 0 个 Live datanodes。
> 真需要重来：先停服务，删掉三台的 `hadoop.tmp.dir` 目录，再格式化。

### 6.2 启动

```bash
start-dfs.sh        # 起 HDFS（NameNode + 所有 DataNode）
start-yarn.sh       # 起 YARN（ResourceManager + 所有 NodeManager）
```

> 💡 案例集群把启停做成了 systemd 服务（`systemctl start hadoop`），
> 好处是开机自启、`journalctl -u hadoop` 直接看日志。学习阶段用脚本启停就够了。

### 6.3 验证（**必须做，不能只看命令没报错**）

```bash
# ① 进程在不在（三台分别看）
jps
# lrh-1 应该看到：NameNode / SecondaryNameNode / ResourceManager / DataNode / NodeManager
# lrh-2/3 应该看到：DataNode / NodeManager

# ② HDFS 健康（★ 最有说服力的一条）
hdfs dfsadmin -report | grep -E "Live datanodes|Dead datanodes"
# 期望：Live datanodes: 3

# ③ YARN 节点数
yarn node -list | grep "Total Nodes"

# ④ 网页能开（在你自己电脑的浏览器）
# http://192.168.87.131:9870   ← HDFS，能浏览文件
# http://192.168.87.131:8088   ← YARN，能看到作业

# ⑤ 真的读写一次（★ 端口在听不等于能干活）
echo "hello hadoop" > /tmp/t.txt
hdfs dfs -mkdir -p /test
hdfs dfs -put /tmp/t.txt /test/
hdfs dfs -cat /test/t.txt
```

**第 ⑤ 条最重要。** 服务的"进程在"和"能干活"是两回事：

> 📌 **本项目对照**：HiveServer2 被 systemd 标记为 `active` 之后，**至少还要等 50 秒**才真正监听 10000 端口。
> 判服务可用必须用**外部判据**（`ss -lntp | grep 10000` + 发一次真实查询），
> **`systemctl is-active` 不算证据**。这条纪律贯穿全课程。

## 七、第六步：装 Hive（让你可以写 SQL）

Hive 依赖：HDFS + YARN 已经跑起来 + 一个关系型数据库存元数据（案例用 MySQL）。

### 7.1 MySQL 建库

```sql
CREATE DATABASE hive DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER 'hive'@'%' IDENTIFIED BY '你的密码';
GRANT ALL PRIVILEGES ON hive.* TO 'hive'@'%';
FLUSH PRIVILEGES;
```

> ⚠️ **必须用 `utf8mb4`**。用 `latin1` 的话，中文表注释会被静默替换成 `?`，
> 案例项目为此专门排查过一轮（根因：Hive 官方 metastore 建表脚本把注释列声明成了 latin1）。
> 而且**用 mysql 客户端要带 `--default-character-set=utf8mb4`**，否则你看上去是正常的、写进去是错的。

### 7.2 `hive-site.xml`

```xml
<configuration>
    <property>
        <name>javax.jdo.option.ConnectionURL</name>
        <value>jdbc:mysql://lrh-1:3306/hive?useUnicode=true&amp;characterEncoding=UTF-8&amp;useSSL=false&amp;serverTimezone=Asia/Shanghai</value>
    </property>
    <property>
        <name>javax.jdo.option.ConnectionDriverName</name>
        <value>com.mysql.cj.jdbc.Driver</value>
    </property>
    <property>
        <name>javax.jdo.option.ConnectionUserName</name>
        <value>hive</value>
    </property>
    <property>
        <name>javax.jdo.option.ConnectionPassword</name>
        <value>你的密码</value>
    </property>
    <property>
        <name>hive.metastore.uris</name>
        <value>thrift://lrh-1:9083</value>
    </property>
    <property>
        <name>hive.metastore.warehouse.dir</name>
        <value>/user/hive/warehouse</value>
    </property>
    <property>
        <name>hive.server2.thrift.bind.host</name>
        <value>lrh-1</value>
    </property>
    <property>
        <name>hive.server2.thrift.port</name>
        <value>10000</value>
    </property>
</configuration>
```

**注意**：XML 里的 `&` 必须写成 `&amp;`，否则文件解析失败。

### 7.3 初始化元数据 + 启动

```bash
# MySQL 驱动放进 Hive 的 lib
cp mysql-connector-j-8.x.jar /opt/hive/apache-hive-3.1.3-bin/lib/

schematool -dbType mysql -initSchema        # 只在第一次做
hive --service metastore &                  # 先起元数据服务
hive --service hiveserver2 &                # 再起 SQL 服务（等 50 秒以上）
```

```bash
# 验证（★ 真实查询，不是只看端口）
/opt/hive/apache-hive-3.1.3-bin/bin/beeline -u jdbc:hive2://lrh-1:10000 -e "SHOW DATABASES;"
```

## 八、第七步：把启停做成服务（可选但强烈推荐）

手动 `start-dfs.sh` 的问题：重启后要记得敲、日志散在各处、不知道上次是几点起的。

```bash
sudo vim /etc/systemd/system/hadoop.service
```

```ini
[Unit]
Description=Hadoop HDFS+YARN
After=network.target

[Service]
Type=forking
User=lrh
Environment=JAVA_HOME=/opt/jdk/jdk1.8.0_202
ExecStart=/opt/hadoop/hadoop-3.3.6/sbin/start-all.sh
ExecStop=/opt/hadoop/hadoop-3.3.6/sbin/stop-all.sh
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now hadoop
systemctl is-active hadoop
journalctl -u hadoop -n 50 --no-pager        # 看日志
```

> 📌 **本项目对照**：案例集群把启停顺序固化进了 systemd。
> 一个重要发现——**从节点的进程应该由从节点自己的服务单元管理**，
> 不要指望"停主节点的 hadoop，从节点会自动停"。
> 实测证伪过：停掉 lrh-1 的 `hadoop` 后，lrh-2/3 上的 DataNode 和 NodeManager **还活着**。
> 所以从节点另建了 `hadoop-worker.service`。**关机时两处都要停，缺一不可。**

## 九、启动/关闭顺序（**不能乱**）

```
开机：
  ZooKeeper(三台) → MySQL → HDFS(NameNode→DataNode) → YARN(RM→NM)
  → Hive(MetaStore→HiveServer2) → DolphinScheduler(master→worker→api)
  → 【验证】3 个 Live datanodes + 真实查询能返回

关机（顺序反过来）：
  停 HDFS/YARN → 停 Hive → 停 MySQL → 停 ZooKeeper → poweroff
```

**规律只有一句**：**一个组件启动时会去连它的依赖。依赖没起来，它就起不来或起不健康。**

反过来，关机先停"上层消费者"：先让没人再写数据，再停存储。

## 十、动手实验室

### 实验 3-1：验收清单（照着打勾）

```bash
# 1. 三台互通
for h in lrh-1 lrh-2 lrh-3; do ssh $h "hostname; uptime"; done

# 2. 进程齐全
jps                                    # 主节点
ssh lrh-2 jps                          # 从节点

# 3. HDFS 健康
hdfs dfsadmin -report | grep -E "Live|Dead|Missing"

# 4. YARN 就绪
yarn node -list

# 5. 真读写
hdfs dfs -put /tmp/t.txt /test/ && hdfs dfs -cat /test/t.txt

# 6. 网页能开
curl -s -o /dev/null -w "%{http_code}\n" http://lrh-1:9870     # 应返回 200
curl -s -o /dev/null -w "%{http_code}\n" http://lrh-1:8088
```

**全部通过才算环境搭好。** 缺一条就别往下走，否则后面所有的错都会叠在这个错上面，你会怀疑人生。

### 实验 3-2：故意破坏，看它怎么报错（**这是最有价值的学习方式**）

```bash
# ① 停掉一个 DataNode，看副本会怎样
ssh lrh-3 "hdfs --daemon stop datanode"
hdfs dfsadmin -report | grep -E "Live|Dead"     # 观察 Live 变成 2
# 想想：刚才上传的文件还能读吗？（能——因为有 3 个副本）

# ② 再启回来
ssh lrh-3 "hdfs --daemon start datanode"
```

**亲手制造一次故障，比读十遍原理有用。** 你会在面试时能讲出"我试过把一台机器停掉，数据还能读"。

### 实验 3-3：算一算你能装多少数据

```bash
hdfs dfsadmin -report | grep -E "Configured Capacity|DFS Remaining"
```

三台各 30GB，副本因子 3 → **可用容量约等于一台机器的容量**。
理解这一点，你才知道为什么"副本 3"是有代价的。

## 十一、常见坑（按出现频率排序）

| 现象 | 根因 | 解法 |
|---|---|---|
| DataNode 起不来 / Live=0 | 重复 `namenode -format` 导致集群 ID 不一致 | 停服务 → 删三台 `hadoop.tmp.dir` → 重新格式化 |
| `start-dfs.sh` 卡住不动 | SSH 免密没配好（含**自己对自己**） | `ssh-copy-id lrh@lrh-1` 别忘了 |
| `Could not find or load main class MRAppMaster` | `mapred-site.xml` 缺 `HADOOP_MAPRED_HOME` | 补三行 env |
| 网页 9870 打不开 | 防火墙 / 绑到了 127.0.0.1 | `sudo ufw disable`；确认绑定主机名不是 localhost |
| reduce 阶段报连不上 | `yarn-site.xml` 缺 `mapreduce_shuffle` | 补上 aux-services |
| 装完用户名不对（`ubuntu@ubuntu`） | VMware 简易安装覆盖了 | 删 `autoinst.iso`，选"稍后安装操作系统" |
| 中文注释变 `?` | 元数据库字符集是 latin1 | 元库用 utf8mb4（详见第 06 章） |
| 一切正常但 SQL 跑不动 | 容器内存不够（本集群上限 2048MB） | 见第 11 章调优 |

## 十二、自测

**每题标了对应的正文小节——答不出来就回去看那节，不要硬想。**

1. `core-site.xml`、`hdfs-site.xml`、`yarn-site.xml`、`mapred-site.xml`、`workers` 各自管什么？—— 对应 **§5.2**
2. 为什么 SSH 免密必须包含"主节点对自己"？—— 对应 **§3.3**
3. `hdfs namenode -format` 为什么只能执行一次？—— 对应 **§6.1**
4. 判断集群真的可用，你会执行哪三条命令？—— 对应 **§6.3**
5. 为什么从节点的进程最好由从节点自己的服务单元管理？—— 对应 **§八**

<details>
<summary><b>参考答案要点</b>（先自己答一遍，再点开核对）</summary>

**1. 五个配置文件**
| 文件 | 管什么 | 案例取值 |
|---|---|---|
| `core-site.xml` | 全局入口 | `fs.defaultFS=hdfs://lrh-1:8020` |
| `hdfs-site.xml` | 存储 | `dfs.replication=3`、name/data 目录 |
| `yarn-site.xml` | 资源调度 | RM 主机、`mapreduce_shuffle`、**容器内存上限 2048MB** |
| `mapred-site.xml` | 计算框架 | `framework.name=yarn` + 三个 `HADOOP_MAPRED_HOME` |
| `workers` | 从节点清单 | 一行一个主机名（Hadoop 2.x 里叫 `slaves`） |

**2. 为什么对自己也要免密**
- `start-dfs.sh` 做的是：读 `workers` 列表（**包含自己**）→ 对每个主机名执行一次 `ssh <主机> 启动进程`
- 轮到本机那一行时，**同样要走 SSH 认证**
- 漏掉的现象：脚本卡在"启动本地 NameNode"不动（对应坑表里的"start-dfs.sh 卡住不动"）

**3. 为什么只能 format 一次**
- `-format` 会清空并重建 NameNode 元数据、生成一个新的**集群 ID**
- DataNode 的 ID 和它对不上 → **DataNode 起不来** → `dfsadmin -report` 显示 `Live datanodes: 0`
- 真要重来：停服务 → 删掉三台的 `hadoop.tmp.dir` → 重新格式化

**4. 三条验证命令（外部判据）**
```bash
jps                                            # ① 进程在
hdfs dfsadmin -report | grep -E "Live|Missing" # ② 健康：Live=3、Missing=0
hdfs dfs -put /tmp/t.txt /test/ && hdfs dfs -cat /test/t.txt   # ③ ★ 真实读写
```
- 加分项：**`systemctl is-active` 不算证据**；YARN 侧用 `yarn node -list`

**5. 为什么从节点要自己的服务单元**
- 实测**证伪**了"停主节点 hadoop 就会停掉从节点进程"：停完 lrh-1 的 `hadoop` 后，
  lrh-2/3 **仍各有 1 个 DataNode + 1 个 NodeManager**，直到 `stop hadoop-worker` 才退出
- 所以：从节点建自己的 `hadoop-worker.service`；**关机时两处都要停，缺一不可**
