## 一、术语速查（按理解顺序排）

| 术语 | 一句话 | 物理上是什么 |
|---|---|---|
| **HDFS** | 分布式文件系统 | 数据切块存多台机器，每块 3 份 |
| **NameNode** | HDFS 的"目录管理员" | 一个 JVM 进程，元数据**在内存**，不碰数据 |
| **DataNode** | 真正存数据块的进程 | 每台机器一个，块是本机磁盘上的普通文件 |
| **SecondaryNameNode** | 定期合并 fsimage + edits | **不是热备份**，挂了不影响运行 |
| **Block（块）** | HDFS 最小存储单位，默认 **128MB** | 一个文件被切成 N 个块文件 |
| **Replication（副本）** | 每块存几份，默认 **3** | 写 1GB 实际写 3GB |
| **YARN** | 资源调度框架（**不计算**） | 决定"这个活派给谁、给多大地方" |
| **ResourceManager** | YARN 的总调度 | 主节点一个进程 |
| **NodeManager** | 每台机器的"工头" | 起容器、监控容器死没死 |
| **ApplicationMaster** | **每个作业一个**的项目经理 | 向 RM 要资源、盯着自己的任务、失败重试 |
| **Container** | 被划出来的资源单位 | **本质是一个被限额的 JVM 进程**（不是 Docker） |
| **MapReduce** | 分布式计算模型 | map（各干各的）→ shuffle（搬）→ reduce（合） |
| **Shuffle** | 把同类数据搬到一起 | **最贵**：落盘 + 跨网络传输 |
| **Hive** | SQL 翻译官 | 把 HQL 编译成 MR 作业 |
| **MetaStore** | 存表结构的地方（在 MySQL） | "表长什么样" |
| **HiveServer2** | 接收 SQL 请求的服务，端口 **10000** | beeline 连的就是它 |
| **beeline** | Hive 的命令行客户端 | JDBC 客户端 |
| **ODS** | 原始数据层，不加工 | 原样落地 |
| **DWD** | 明细清洗层 | 去重/解析/归一，保留最细粒度 |
| **DIM** | 维度层 | 一行一个实体（商品/用户/日期） |
| **DWS** | 汇总层 | 按主题聚合，供复用 |
| **ADS** | 应用层 | 一个业务问题一张表 |
| **粒度（Grain）** | **这张表的一行代表什么** | 建模第一件事 |
| **事实表** | 记"发生了什么动作" | 金额、次数 |
| **维度表** | 记"参与者是谁" | 名称、类目、品牌 |
| **星型模型** | 事实表在中间、维度表围一圈 | 靠 ID 关联 |
| **SCD** | 缓慢变化维 | Type1 覆盖 / Type2 加版本行 |
| **分区（Partition）** | 按某个字段分目录 | `dt=2019-10-01/` 是 HDFS 上的一个子目录 |
| **动态分区** | 分区值来自 SELECT 的最后一列 | 一次写 N 个分区（需 4 行 SET） |
| **ORC / Parquet** | 列式存储格式 | 只读需要的列 → IO 少一个数量级 |
| **数据倾斜** | 个别 key 特别大 | 表现：卡在 99% |
| **幂等** | 重跑 N 次结果一样 | 靠 `INSERT OVERWRITE` |
| **T+1** | 今天算昨天的数据 | 离线数仓的典型节奏 |
| **DAG** | 有向无环图 | 调度里的工作流图 |
| **ZooKeeper** | 分布式协调服务 | 记"谁在线"、仲裁 |
| **DolphinScheduler** | 工作流调度系统 | 定时、依赖、重跑、告警 |
| **ECharts** | 前端图表库 | 把数据画成图 |

## 二、命令卡

### 2.1 Linux 日常

```bash
pwd / ls -lh / cd / mkdir -p / rm -rf          # 走位与文件
cat / less / head -20 / tail -f                # 看文件（日志用 tail -f）
grep -n "ERROR" x.log / grep -r "key" dir/     # 搜索
wc -l / sort | uniq -c / du -sh / df -h        # 统计
awk -F',' '{print $1}' / sed -n '10,20p'       # 取列 / 取行

ssh lrh@lrh-2 / scp file lrh@lrh-1:/tmp/       # 远程
setsid nohup bash run.sh > run.log 2>&1 &      # ★ 后台长任务
```

```bash

hdfs dfsadmin -safemode get|leave
```

## 五、写 SQL 的固定模板（复制粘贴用）

### 5.1 写分区表必备 4 行

```sql
SET hive.exec.dynamic.partition = true;
SET hive.exec.dynamic.partition.mode = nonstrict;
SET hive.exec.max.dynamic.partitions = 200;
SET hive.exec.max.dynamic.partitions.pernode = 100;
```

### 5.2 一次扫描多口径

```sql
COUNT(CASE WHEN event_type = 'view' THEN 1 END) AS pv_cnt
SUM(CASE WHEN event_type = 'purchase' THEN price ELSE 0 END) AS gmv
COUNT(DISTINCT CASE WHEN event_type='purchase' THEN user_id END) AS buyer_cnt
```

### 5.3 窗口函数四件套

```sql
MIN(dt)  OVER (PARTITION BY user_id)                       -- 首次
LAG(dt)  OVER (PARTITION BY user_id ORDER BY dt)           -- 上一次
ROW_NUMBER() OVER (PARTITION BY dt ORDER BY gmv DESC)      -- 排名
SUM(x) OVER (PARTITION BY k ORDER BY dt
             ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)  -- 累计
```

### 5.4 防除零 + 控制精度

```sql
ROUND(a * 1.0 / NULLIF(b, 0), 4)
```

### 5.5 空值归一（**避免 NULL 干扰 GROUP BY**）

```sql
COALESCE(NULLIF(brand, ''), 'unknown')
```

### 5.6 校验三件套

```sql
SELECT COUNT(DISTINCT dt) AS part_cnt, COUNT(1) AS row_cnt FROM t;   -- 结构+行数
-- 交叉对账：换一条路径算同一个指标
-- 方向性违例：下面这些应返回 0 行
SELECT dt FROM ads_x WHERE dau < new_dau;
```

## 六、报错速查（只看这张表）

| 你看到的 | 第一反应 |
|---|---|
| `Error 10096` | 补动态分区 4 行 SET |
| `Error 10004` | `DESC` 一遍所有涉及的表 |
| `Error 10011 ... sequence` | 用了 Spark 函数，换 Hive 写法 |
| `GC overhead limit exceeded` | **加内存**（去 Diagnostic Messages 找） |
| `exceeding memory limits` | 调大 `memory.mb` 和 `-Xmx` |
| `Exit code 143` | 被人停了，不是 bug |
| `Exit code 137` | OOM，查内存 |
| 一直 ACCEPTED | 资源满了，看 8088 |
| 卡在 99% | 数据倾斜 |
| `Under-replicated` | **先看副本因子**，可能是假警报 |
| `Live datanodes: 0` | 重复 format，清 tmp 重来 |
| 中文变 `?` | 元数据库字符集 |
| 页面白屏 | `file://` 下不能用 fetch；三个文件要同目录 |

## 七、四条纪律（贴在显示器上）

1. **说"好了"必须给外部判据** —— `systemctl is-active` 不算证据
2. **退出码先于日志文本** —— 143 是被人停的，137 是 OOM
3. **控制面 ≠ 数据面** —— 调度说停了，要自己去 `ps` 和 `yarn application -list` 确认
4. **错误的原因比错误的现象更危险** —— 写原因时问自己"我怎么证明这个因果"
