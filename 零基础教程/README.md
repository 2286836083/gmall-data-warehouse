# 零基础大数据开发教程 · 课程总纲

> **这门课的目标**：让一个没接触过大数据开发的人，按顺序读完并动手做完之后，
> 能**独立**完成这件事——拿到一份原始数据，自己设计分层、写 ETL、跑通调度、做出报表，并能在出错时定位原因。
>
> 全部案例取自一个真实跑通的项目（gmall 电商数仓，三节点 VMware 集群，1063 万行真实数据），
> **所有数字都有出处**，不是教科书上的示例值。

建立日期：2026-10-06 ｜ 配套项目：`D:\数据开发\`

## 〇、先搞清楚：这套教程和仓库里其他文档是什么关系

仓库里已经有三类文档，它们**各有分工，不要混着读**：

| 文档 | 讲什么 | 什么时候读 |
|---|---|---|
| **本教程（零基础教程/）** | **教你这门手艺**：为什么这么做、怎么从零做出来、怎么做决策 | **你现在的默认选择**——按顺序读 |
| `项目产出/组件详解/` | 逐个组件科普（虚拟机/JVM、HDFS、YARN、Hive、DS、可视化） | 想对某个组件再深入一层时，作为本教程的补充读物 |
| `手把手教程/` | **本项目集群的操作手册**（照抄命令把这套环境跑一遍） | 你已经有环境、只想把它跑起来时 |
| `实验分析/` | 每一次实验与故障的原始记录（假设→实测→结论） | 想看"某个结论是怎么被证明的"时 |
| `CONTEXT.md` | 项目事实速查（路径/端口/陷阱） | 换环境、查参数时 |

一句话：**本教程教你钓鱼，`手把手教程`给你这口塘的地图，`实验分析`是钓鱼日志。**

## 一、学完你能做什么（验收标准）

读完不应该只是"知道名词"，而是能交付下面这些东西。它们同时就是**毕业项目**（第 12 章）的验收清单：

| # | 能力 | 交付物 | 对应章节 |
|---|---|---|---|
| 1 | 能自己装出一套能跑的 Hadoop 集群 | 三节点集群 + `hdfs dfsadmin -report` 显示 3 个 Live datanodes | 02、03 |
| 2 | 能解释数据是怎么存、怎么算的 | 画出一次 SQL 从提交到落盘的物理路径 | 04、05 |
| 3 | 能用 SQL 建表、装载、清洗、聚合 | 一套可重跑的 HQL 脚本 | 06 |
| 4 | **能自己设计分层和粒度** | 一份建表设计文档，每张表写清粒度 | 07 |
| 5 | 能端到端跑通一条链路 | ODS→DWD→DWS→ADS 全部落表 + 行数对账表 | 08 |
| 6 | 能让它每天自动跑 | 一条调度工作流 + 一次成功实例 | 09 |
| 7 | 能把结果画给人看 | 一个离线可打开的可视化页面 | 10 |
| 8 | **出错时不靠猜** | 一份"现象→定位命令→根因→解法"的排错笔记 | 11 |

> 第 4 条和第 8 条是最容易被忽略、也最区分水平的。
> 会写 SQL 的人很多，能说清"这张表一行代表什么"、能在报错后找对方向的人很少。

## 二、学习路线图

```
第 1 阶段：建立心智模型（别急着敲命令）
  ├─ 01 导论：大数据到底在解决什么问题          ← 先搞懂"为什么"，后面才不会死记命令
  └─ 02 Linux 与 Shell 生存手册                ← 集群没有图形界面，这是你的手和眼

第 2 阶段：把环境搭出来（第一次成就感）
  ├─ 03 从零搭一套三节点集群                   ← 里程碑①：3 个 DataNode 在线
  ├─ 04 HDFS：数据怎么存                       ← 里程碑②：亲手看一个文件被切成块、存三份
  └─ 05 YARN 与 MapReduce：活怎么干            ← 里程碑③：跑通 wordcount，看懂 shuffle

第 3 阶段：用 SQL 干活（从这里开始像"开发"了）
  └─ 06 Hive 与 HQL                            ← 里程碑④：建库建表、装载 CSV、跑出聚合结果

第 4 阶段：学会设计（★ 全课最重要）
  ├─ 07 维度建模与分层设计                     ← 里程碑⑤：为一份新数据写出建表设计
  └─ 08 实战：从原始数据到第一张报表            ← 里程碑⑥：完整跑通 1063 万行数据链路

第 5 阶段：让它变成"产品"
  ├─ 09 DolphinScheduler 调度                  ← 里程碑⑦：定时自动跑，不用人盯
  └─ 10 可视化：把 Hive 表变成一张图            ← 里程碑⑧：一个双击就能打开的大屏

第 6 阶段：能扛事
  ├─ 11 调优与排错                             ← 里程碑⑨：报错时能给出方向，而不是重启试试
  └─ 12 毕业项目：独立做一遍                    ← 里程碑⑩：自己从零交付一个完整项目

附录：13 术语速查与命令卡（随时翻）
```

**建议节奏**：第 1–3 阶段每章半天（要动手），第 4 阶段每章一天（要想），第 5–6 阶段每章半天。

## 四、动手需要什么（硬件与环境）

本教程的案例集群长这样（**这是真实配置，不是推荐配置**，你可以比它小）：

| 项 | 案例集群 | 说明 |
|---|---|---|
| 宿主机 | Windows + VMware Workstation | 至少 **16GB 内存**；低于 8GB 建议只开单节点伪分布式 |
| 虚拟机 | 3 台 Ubuntu（桌面版可关掉，省 600MB/台） | 主机名 lrh-1 / lrh-2 / lrh-3 |
| 内存分配 | lrh-1 **7168MB**、lrh-2 **3392MB**、lrh-3 **4096MB** | 不是平均分——见下面那条 |
| 磁盘 | 每台 30GB | HDFS 数据 + 日志 |
| 网络 | VMware NAT，三台静态内网 IP，写死 `/etc/hosts` | 集群内靠主机名互相访问 |

> **为什么 lrh-1 内存给得多？**
> 因为它要跑 9 个 Java 进程（NameNode、ResourceManager、Hive、MySQL、DS master…），另外两台只跑 4 个。
> 最初三台平均分（各 4GB），结果 lrh-1 可用内存只剩 601MB 开始用 swap（把内存挪到硬盘，慢几十倍），
> 而最闲的机器还有 2GB 空着。**资源分配要按负载、不按均分**——这是真实踩过的坑（见 `实验分析/实验01_集群内存调优.md`）。

**软件版本（案例集群）**：

| 组件 | 版本 | 为什么是这个版本 |
|---|---|---|
| JDK | 8（`/opt/jdk/jdk1.8.0_202`） | Hadoop 3.x 生态的事实标准；Spark 4.x 要 JDK 17+ |
| Hadoop | 3.3.6 | 稳定版，资料多 |
| Hive | 3.1.3 | 配 JDK 8 的常用组合 |
| Spark | 3.5.9 | **JDK 8 支持的最后一条主线**（4.x 要 JDK 17+，且默认 ANSI 模式会改 SQL 语义） |
| MySQL | 8 | 存 Hive 元数据与 DS 元数据 |
| ZooKeeper | 3.8.7 | 集群仲裁 |
| DolphinScheduler | 3.1.8 | 国产调度，中文界面、Web 拖拽编排 |

## 五、这套教程的写法约定（先说清楚，免得你误解）

1. **类比之后一定紧跟"物理上是什么"。**
   "像图书馆"这种话只能帮你建立第一印象，真正管用的是"它写在哪个进程的内存里、走没走网络、落在哪块磁盘上"。

2. **所有命令和数值都标注来源。**
   - 标 `【实测】` 的，来自案例集群的真实运行记录，并注明日期
   - 标 `【模板】` 的，是可抄的通用写法，但**不是**从某台机器上抓下来的
   - 标 `【未验证】` 的，是我判断应该如此但没亲手跑过的——你可以验证后告诉我

3. **命令里的占位符**：`<主机名>`、`<你的用户名>`、`/path/to/...` 都需要你替换。
   案例集群的对应值会在旁边以「本项目对照」的形式给出。

4. **被证伪的说法我会明写。**
   包括我自己判断错过的。只讲成功的教程等于宣传材料，你会带着错误的世界观去排查问题，而且永远发现不了。

5. **每章结构固定**：
   `这章解决什么问题 → 原理（机制/顺序/硬件）→ 怎么做 → 动手实验室 → 常见坑 → 自测`

## 六、开始之前的一句话

大数据开发这件事，真正难的不是记住几十个命令，而是建立**"我敲下回车之后，物理上发生了什么"**的心智模型。

有了它，报错信息对你来说是一份线索；没有它，报错信息只是一堵墙。

**从这个角度说，第 01、05、11 三章是这套教程最值钱的部分。**
