# 待问问题

> **用法**：想到什么就在下面「待处理」区加一行。攒够一批，让 AI 一次处理。  
> **为什么要攒**：零散问答最亏的是**每次都要重新加载一遍项目上下文**。十个问题批量处理，可能比一个个问省一半轮次。
>
> **AI 处理时请遵守**：
>
> 1. 先读 `CONTEXT.md` + `项目状态.md` 再动手
> 2. 按下方「类型」决定产出到哪（见文末对照表）
> 3. **凡影响项目决定的结论，必须落盘到 `实验分析/` 或记忆** —— 否则按约定视为未决定
> 4. 处理完把条目移到下方「已处理」区，并注明产出位置

## 提问方式的小建议

**问得越具体，产出越能用**：

| ❌ 不好         | ✅ 好                                                     |
| ------------ | ------------------------------------------------------- |
| "Spark 怎么样？" | "Spark 和 Hive 在 shuffle 上有什么区别？为什么 Spark 能省掉落盘？"        |
| "为什么报错？"     | "报 `GC overhead limit exceeded`，我想知道是容器内存不够还是代码问题，怎么区分" |
| "帮我优化一下"     | "DWS 商品主题跑 637 秒失败，`HDFS Read` 只有 21.9MB，该往哪个方向调"       |

**一个万能问法**（项目已有的框架）：遇到任何"慢/卡/失败"，先问 ——

> **它是算不过来、写不过来、还是搬不过来？**
>
> 详见 `实验分析/_提问框架_拆解分布式系统.md`（7 个固定问题 + 每个都配可跑命令）

**还有一招最有价值**：把问题当**下单**，而不是问答。

> 你之前问"我不知道出了什么问题"，产出的不是一段回答，而是 **7 份执行原理文档**。  
> **凡是值得问第二遍的，就该变成文档。**
