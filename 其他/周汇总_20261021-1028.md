## 三、关键结论（可直接拿去面试讲）

1. **三种关系必须分清**（面试第一道陷阱题）：Hive on Spark / **Spark SQL + Hive Metastore（本项目）** / Spark 完全独立。
   "Spark 是 Hive 的执行引擎"**只对第一种成立**。
2. **Metastore 之于表 = NameNode 之于数据块**：都是目录服务，都不碰数据。
   `show tables` 快、`select count(*)` 慢，分界线就是"碰不碰数据"这条线。
3. **双引擎数据一致是天然的**（同一份 HDFS 文件 + 同一份元数据，不存在两份数据）。
   → 所以对账验的是**计算逻辑**，不是数据同步。这比"我看结果觉得对"高一个档次。
4. **Hive 在本项目里没有一项职责是"跑计算"**：提供 Metastore / 提供建表规范 / 提供对照基线。
   HiveServer2 可去，**Metastore 几乎不可去**。
5. ⚠️ **一处不能当实测讲**：Spark 内置 Hive 客户端 2.3.9 vs 集群 Metastore 3.1.3 的版本不匹配。
   本项目是**先配好再跑的，没留报错现场** → 只能说"按版本对齐设计的，机制上推断会连不上，**但没实测**"。
6. **简历的改动逻辑**：去掉形容词，换可验证行为。
   例："适应加班及特殊时段值班安排" → "有工程化习惯：维护文档体系与实验报告，保证结论可复现可交接"；
   "GitHub、B 站" → "Git、Linux 常用命令；习惯通过官方文档与源码定位问题"。
